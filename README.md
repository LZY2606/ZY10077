# 结构迁移本地沙箱演练（Migration Sandbox）

在**本地、无外部网络依赖**的环境里演练数据库结构迁移：定义表结构快照、迁移步骤、前置条件与跨表不变量；
系统为每次运行创建隔离副本，按步骤写入可恢复日志（WAL），允许在任意声明的故障点模拟进程退出；
重启后基于「日志 + 数据探针」判定每一步是**从未开始、已完整提交、可自动续跑，还是无法证明安全、必须停住等待人工决定**——
绝不凭步骤名字或类型猜测重跑。

内置示例迁移 `orders -> orders_v2`，覆盖：

- **DDL**：新建结构（带对象存在性探针，支持崩溃后证明已提交）
- **分批回填**：稳定主键（keyset）边界、每批原子提交、批次行数与校验摘要、晚到行不丢不重
- **双写窗口**：开窗前存量对账、窗口双写/仅旧写、关窗自动对账补齐、新旧读路径一致性
- **副作用步骤**：外部通知这类**无法由沙箱探针证明**的操作，崩溃后必须 HALTED 等待人工裁定
- **完成判定**：结构/不变量/读路径/**WAL 终局事件**全部满足才算成功，命令返回零不算

## 技术栈

- Java 21+（在 JDK 24 上验证）、Spring Boot 3.5、Spring JDBC
- H2 文件数据库（控制面 + 每个运行一个独立 schema 作为数据面），零外部服务
- 原生 HTML/CSS/JS 单页，无前端构建步骤
- 依赖可离线（本机 `~/.m2` 已缓存所需构件）

## 安装、测试、启动

在仓库根目录：

```bash
./mvnw -q -DskipTests package
./mvnw -q test && ./mvnw -q spring-boot:run -Dspring-boot.run.arguments=--server.port=5209
```

可见页面：<http://127.0.0.1:5209>

数据文件在 `./data/migsb.*`（H2）。删除该目录可回到全新状态，首次启动会播种示例定义。

## 复现一次故障恢复（新维护者上手路径）

以“**回填进行到批次边界时进程退出**”为例，大约 2 分钟：

1. 启动应用，打开 <http://127.0.0.1:5209>，进入「演练运行」。
2. 定义选择 `订单表演练...`，故障点选择
   `backfill_orders / 第二批提交边界崩溃 [MID_BATCH]`，点「创建隔离副本」。
3. 点「继续推进」。生产模式下进程会在该点**立即退出**（`Runtime.halt(3)`，跳过 shutdown hook，最接近被杀死）；
   页面随之无法访问。
4. 重新执行启动命令。启动时恢复扫描器自动运行，日志与运行详情中会出现
   `RECOVERY_VERDICT = RESUMABLE`，原因里给出 **WAL 游标与已提交批次数**。
5. 在运行详情点「继续推进」：引擎从最后一个稳定主键边界续跑，页面可见每批行数、pk 区间与批次校验摘要。
6. 进入双写窗口后，先发一条「双写两表」，再发一条「仅旧表」（模拟回填后到达、主键低于结束游标的新行），
   点「对账并关窗」——仅旧表行被幂等补齐，不丢不重。
7. 最后一次「继续推进」执行完成判定：行数不变量、有序校验摘要不变量、旧/新读路径结果，
   以及 `RUN_COMPLETED` 终局事件全部满足后，状态才变为 `COMMITTED`。

### 必须人工决定的中间态

选择 `notify_downstream / 通知发出后崩溃 [AFTER_APPLY]` 重复上述流程。

该步骤代表“通知下游切换读路径”，沙箱内没有探针能证明通知是否真的送达。重启后恢复判定为
`UNCERTAIN`，运行被置为 `HALTED`，自动推进被拒绝（页面与 API 都会明确报错）。此时只能：

- **确认提交**：在外部系统核实副作用确实生效后，记录裁定依据并提交；或
- **补偿并回滚**：按步骤定义的 `compensate` 逆序补偿，终局记为 `ROLLED_BACK`。

DDL 步骤若声明了 `probeType: TABLE_EXISTS`，崩溃后可以用对象存在性证明已提交；
**未声明探针**的 DDL 在 `AFTER_APPLY` 崩溃同样会落到 `UNCERTAIN`，而不是盲目重跑。

## 判定语义（重启恢复扫描器）

扫描器只依据两类证据，不依赖步骤命名：

| 情况 | 判定 | 后续 |
|---|---|---|
| 无 `STEP_STARTED` | `NOT_STARTED` | 直接执行 |
| 有 `STEP_COMMITTED`，或探针/行数+校验摘要证明完成 | `COMMITTED` | 跳过 |
| 回填已有提交批次且目标是源的子集 | `RESUMABLE` | 以 WAL 主键游标续跑（先截断无日志的尾部） |
| 双写窗口在打开状态崩溃 | `WINDOW_OPEN` | 可继续写入；关窗对账自动补齐 |
| 回滚过程崩溃 | `ROLLBACK_RESUMABLE` | 幂等继续逆序补偿 |
| 副作用/无探针 DDL 崩溃、或日志与数据矛盾 | `UNCERTAIN` | **HALTED，等待人工裁定** |
| 全部步骤提交但缺终局事件 | 重新执行完成判定 | 不变量+读路径+`RUN_COMPLETED` |

回填游标是稳定主键边界（`WHERE pk > :cursor ORDER BY pk LIMIT n`），每批的「MERGE 数据 + 批次记录 + WAL」
在同一事务提交；崩溃时不存在“数据写了但日志没记”的批次。目标表中超过已记录游标的无日志尾行会在续跑前删除。
窗口关窗前的全量对账负责兜底窗口期间插入的任何晚到行（包括主键低于回填结束游标的行）。

## 定义版本、指纹与分支

- 定义内容经规范化 JSON（键排序）后取 SHA-256 作为**指纹**；每个运行创建时绑定一个具体指纹，
  之后定义被修改**不影响**已有运行。
- 提交定义时携带浏览器所持有的 `baseFingerprint`（乐观锁）。两个浏览器基于同一旧版本先后提交，
  后到一方收到 **409 冲突**，页面展示对方当前 head 内容，供其重新合并；可以选择推进 head 或**保存为分支**
  （分支不移动 head）。

## 演练证据：只追加 + 可重放

- 「证据库」页可按定义导出证据包（JSON），内含定义指纹、每个运行的步骤/批次/完整 WAL/读路径检查/不变量结果、
  声明的故障点预期，以及包指纹与规则版本（`migsb-evidence-v1` / `rules-v1`）。
- 导入时**原始证据只追加**：`evidence_receipt` 表由 H2 触发器拒绝 UPDATE/DELETE；
  同一证据重复导入幂等。派生出的验证报告单独存储，带**规则版本与来源指纹**，不改写原始记录。
- 重放验证会核对：包指纹与定义指纹、每个声明故障点是否存在对应演练运行及其 `RECOVERY_VERDICT` 是否符合预期、
  批次序号连续性与游标不倒退、终局状态必须有对应 WAL 终局事件、读路径与不变量结果。
  任何字段被篡改都会导致包指纹失配并在报告中逐条列出问题。

## 测试（不依赖外部网络）

```bash
./mvnw -q test
```

集成测试为每个用例分配独立的 H2 文件目录；崩溃用例在第一个 Spring 上下文触发“进程退出”
（`crashtest` profile 的替身抛出异常，等同于生产 `halt` 前已把 WAL 落盘），
随后**启动第二个上下文指向同一文件库**执行真实恢复：

- 正常全流程（双写、晚到行、终局判定）
- 回填批次边界崩溃 → RESUMABLE 续跑，无丢失/重复
- 双写开窗后崩溃 → 重启识别 WINDOW_OPEN 并对账
- 副作用崩溃 → UNCERTAIN/HALTED，拒绝自动重跑，接受人工提交
- 定义乐观冲突与分支不移动 head
- 原始证据只追加 + 重复导入幂等
- 为**全部声明故障点**各跑一遍崩溃-恢复，导出证据并重放验证，再验证篡改会被发现

## 主要代码地图

- `domain/MigrationSpec.java`：迁移定义的类型化模型（快照、步骤、故障点、不变量、读路径）
- `domain/Fp.java`：规范 JSON 与 SHA-256 指纹
- `engine/MigrationEngine.java`：创建副本、推进步骤、回填、双写、完成判定、人工裁定、回滚
- `engine/RecoveryScanner.java`：重启三态判定（日志 + 探针）
- `engine/SandboxService.java`：隔离 schema、keyset 分批、MERGE 对账、规范化校验摘要
- `engine/ProductionCrashSimulator.java` / `TestCrashSimulator.java`：进程退出与测试替身
- `svc/DefinitionService.java`：指纹、家族/分支、乐观冲突
- `svc/EvidenceService.java`：证据导出、只追加接收、规则 v1 重放验证
- `resources/schema.sql`：控制面表结构与证据不可变触发器
- `resources/static/`：单页界面
